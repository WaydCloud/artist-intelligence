## 1. 탭 스모크 (`apps/dashboard/scripts/smoke-tabs.mjs`)

`cd apps/dashboard && npm run smoke:tabs` (dev 실행 중일 때). 탭 × 테마마다 검사:

1. 콘솔 에러 · 페이지 예외 0건
2. `main`이 비어 있지 않음(≥200자) — **전체 언마운트 감지**
3. 리포트 제목 렌더
4. `ChartBoundary` 폴백으로 떨어진 카드 없음
5. 내용 없는 카드 없음 — 뷰 미구현 감지
6. `<details>` 전부 펼친 뒤에도 1~5 유지

- **playwright를 devDependency로 넣지 않았다**(AGENTS §1: 새 의존성은 승인). 로컬 → `PLAYWRIGHT_DIR` → 전역 `@playwright/mcp` 동봉분 순으로 찾는다. **없으면 조용히 넘어가지 않고 exit 1** — 검사기가 아무것도 안 하고 초록인 상태(0바이트 시크릿 스캔과 같은 함정)를 만들지 않는다.
- ⚠ **브라우저 리비전 불일치는 상수다.** 전역 playwright가 기대하는 리비전(1226)과 설치된 것(1228)이 어긋났다. `ms-playwright`에서 설치된 것 중 가장 새 것을 찾아 `executablePath`로 직접 짚는다(`PLAYWRIGHT_CHROMIUM`으로 덮어쓰기 가능).
- ⚠ **playwright는 CJS다.** 동적 `import()`로 받으면 named export가 비어 `chromium`이 undefined가 된다 — `require`로 읽어야 한다(첫 시도에서 걸렸다).

### 🔴 더 큰 결함: 재개 기계장치가 부분 실패에는 안 돌고 있었다

`daily_collect.ps1`이 마지막에 `Save-State $true`를 **무조건** 호출했다. 그래서 `Set-LegResult`가 남긴 `pending` 타깃이 **한 번도 재시도되지 않았다** — 2시간 뒤 시도가 `done=true`를 보고 즉시 no-op으로 나갔기 때문이다. **D-018 재개는 스크립트가 중간에 죽은 경우만 살렸고, 부분 실패는 못 살렸다.** 오늘 Apple 9개가 살아난 것은 재시도가 파이썬 안으로 들어갔기 때문이고 그 바깥은 여전히 새는 구조였다.

- 무료 수집 레그에 pending이 남으면 하루를 **의도적으로 미완**으로 둔다 → 다음 시도가 실패 타깃만 다시 걷는다.
- **4회 시도(=8시간)** 뒤에는 결손을 확정하고 무엇이 비었는지 로그에 남긴다. 무한 재시도는 그 날짜를 영원히 `done`이 안 되게 만들어 GAP 경보를 매일 울린다.
- 4분기 전부 실측 확인(all ok / partial 1회 / partial 4회 / 유료만 실패).
- Kworb 레그가 `2>$null`로 삼키던 **실패 사유를 로그에 남긴다.** 판정도 `$?` → `$LASTEXITCODE`(stderr 리다이렉트 시 PS 5.1이 종료코드 0에도 `$?`를 false로 만든다 — sonic 레그가 이미 걸렸던 함정).

## 4. 차트 데이터 계약 게이트 (`scripts/validate_report_data.py`) — 후속 발견

**탭 스모크에 구멍이 있었다.** 7-30 결함 3건 중 세 번째(막대 11개가 이름 없이 그려짐)를 재현해 넣었더니 **스모크가 PASS했다** — 이름이 비어도 카드에 값은 남아 "내용 없는 카드" 검사를 빠져나간다. DOM에서 잡으려면 취약해지므로 **데이터 층에서 잡는 것이 맞다.**

- `report.schema.json`이 `"data": {}`라 차트 페이로드를 전혀 제약하지 않는다(§D 8번). 스키마 수정은 승인이 전제라, **스키마를 건드리지 않는 별도 검사기**를 만들어 CI `schema-validate` 잡에 붙였다.
- 잡는 것: bar `name` 누락/`value` 비수치 · line 시리즈 길이 불일치(렌더가 죽지 않고 **말없이 어긋난 점을 그린다** — 더 나쁘다) · heatmap 셀 격자 불일치 · **대시보드가 모르는 tunable `view`**(7-30 두 번째 결함) · 노브 범위 밖 기본값(반박 불가한 임계).
- **tunable `view` 목록은 렌더러(`Tunable.tsx`)에서 정규식으로 직접 읽는다** — 목록을 검사기에 박으면 새 뷰마다 두 곳이 어긋난다. 못 읽으면 조용히 넘기지 않고 실패한다.
- `--selftest` **14/14**(검출 기대 9 · 통과 기대 5). CI는 selftest를 먼저 돌려 **게이트 자체가 살아 있는지** 확인한 뒤 전수 검사한다.
- ⚠ **정공법은 여전히 열려 있다**: 계약이 기계가 읽는 한 곳(스키마)에 있어야 한다. 지금은 읽는 쪽 기대가 파이썬에 있어 **모듈 CLI 단계에서는 계약 이탈이 통과하고 CI에서만 걸린다.**

## 5. 리포트 계약이 차트 페이로드를 제약하게 됐다 (D-036 · 승인 후 같은 세션)

도메인 소유자가 **시각화 단계 전환**을 예고하며 끊는 선을 물었고, 판단 기준을 "남은 데이터 작업이 렌더 **형태**를 바꾸는가 **행**만 늘리는가"로 잡았다. 전수 확인 결과 형태를 바꾸는 항목이 **계약 하나뿐**이어서 그것만 전제로 올려 승인받았다. 판단 근거·결정 내용은 [`docs/DECISIONS.md`](../docs/DECISIONS.md) D-036.

- 스키마에 `chart.type` → `chart.data` 판별 분기를 넣었다(bar·line·heatmap·tunable). **기존 6종은 이미 계약을 지키고 있었다**(6/6 통과) — 잡은 것은 앞으로의 이탈이다.
- **읽는 쪽 동시 갱신**(AGENTS §0): `Chart`를 판별 유니온으로. 예전 `data: ... | unknown` + `as BarData` 캐스트 4개가 **타입 검사를 무력화하고 있었고**, 그게 7-30 결함이 typecheck를 통과한 이유다. 캐스트가 사라졌다.
- **얻은 것(실측)**: `validate_report`에 `label` 오용 리포트를 넣으면 **오류 2건으로 쓰기를 거부한다.** 이전엔 CI까지, 그 전엔 사람 눈까지 갔다.
- **두 층 분업을 한 곳에서 증명한다**: `validate_report_data.py --selftest` → **34/34**(스키마 20 · 검사기 14). 스키마=형태 / 검사기=교차 필드 길이·렌더러 결합·범위. 일부 겹치는 것은 의도다 — 이 스크립트는 stdlib만 써서 jsonschema 없는 환경에서도 단독으로 돌아야 한다.
- **tunable 뷰별 페이로드는 일부러 제약하지 않았다.** 정본은 렌더러이고, 스키마에 5종을 베끼면 **새 뷰마다 승인이 필요해진다**(AGENTS §0). 대신 검사기가 렌더러를 직접 읽는다.
- 📌 **끊는 선 판단에 쓴 사실**: 마디 격자 32칸조차 형태를 안 바꾼다(`cosine(profile, positions, bins)` — 16 가정 없음) · `KpiTile`은 `Metric`에 일반적 · 시간 깊이 social 103일 / chart 14 / yt 7 / **sonic 3**.

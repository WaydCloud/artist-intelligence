# sonic-profile · TESTS (값 무결성 검증)

> [`RULES.md`](RULES.md) §3 원장의 각 항목은 여기서 검증된다. **네트워크 없이 도는 것**이 스모크의 조건.
> 결정 근거: [`../../docs/DECISIONS.md`](../../docs/DECISIONS.md) D-019.

## 1. 픽스처 전략 — 합성 신호 (저작물 미사용)

원본 오디오를 저장하지 않는 것이 이 모듈의 불변식이므로(RULES §1), **픽스처도 음원이 아니다.** numpy로 생성한 **합성 신호**를 쓴다 — 정답을 우리가 알고 있다는 점에서 오히려 검증에 유리하다.

| 픽스처 | 생성 | 검증하는 것 |
|---|---|---|
| `click_120bpm` | 120 BPM 간격 클릭 트레인 | tempo_bpm이 120(±허용오차), pulse_clarity 높음 |
| `click_90bpm` | 90 BPM 클릭 | **옥타브 오류 회귀 방지**(180·45로 튀지 않는가) |
| `noise_white` | 백색잡음 | pulse_clarity 낮음, tempo 신뢰도 플래그 off |
| `sine_50hz` + `sine_4khz` | 저역/고역 정현파 | low_end_ratio가 각각 ~1.0 / ~0.0, brightness 단조 증가 |
| `silence` | 무음 | **미해석 처리**(0으로 채우지 않음) |
| `too_short` | 1초 | 길이 미달 → 미해석 |

## 2. 필수 통과 항목

- **결정성**: 같은 입력 → 같은 출력. 동일 픽스처를 2회 분석해 **비트 단위로 동일**해야 한다(난수·시각 의존 금지).
- **미해석 규약**: 무음·과단축·디코드 실패가 `0`이 아니라 **결측**으로 나오는가. 결측이 집계 평균을 끌어내리지 않는가(결측 ≠ 0, §0).
- **스키마**: `sonic-profile validate output/report.json` 통과.
- **관측 0 케이스**: 입력이 비어도 크래시하지 않고 유효 report + "관측 없음" insight를 내는가.
- **한계 문구 전파**: report의 `insights`에 RULES §3.1의 "곡 간 단일 비교 금지"와 커버리지가 **실제로 들어 있는가**(문자열 존재 검사). 한계 병기는 선택이 아니라 §5 준수 요건이므로 테스트한다.
- **무보관**: `fetch` 실행 후 임시 디렉터리에 오디오 파일이 **남아 있지 않은가**. 예외 발생 경로에서도 삭제되는가(실패 주입 테스트).

## 3. `crest_factor_db` 검증 — **통과 (2026-07-28)** → 활성화

**질문**: Apple 프리뷰에 라우드니스 정규화가 걸려 있는가? 걸려 있다면 crest factor는 마스터링이 아니라 Apple의 처리 파이프라인을 측정하게 된다.

**설계**: 압축 강도가 뚜렷이 다를 것으로 예상되는 10곡(현대 EDM/K-pop/힙합 vs 클래식·재즈·1960~70년대 녹음·앰비언트)의 프리뷰 RMS·peak를 비교. 정규화가 걸려 있으면 RMS가 좁게 뭉친다. 판정 기준은 **결과를 보기 전에** 고정: 스프레드 < 2dB → 정규화 의심(비활성 유지) · ≥ 6dB → 정규화 없음(활성 가능).

**결과**: RMS 범위 **−24.50 ~ −5.05 dB (스프레드 19.46 dB, σ 6.34)** — 기준을 크게 넘겼다. 순서도 마스터링 이론과 일치한다.

| 표본 | RMS | crest |
|---|---|---|
| 현대 K-pop (CORTIS - REDRED) | −5.05 dB | 8.23 dB |
| 현대 힙합 (Kendrick Lamar) | −5.81 dB | 9.35 dB |
| 현대 EDM (David Guetta) | −7.73 dB | 11.02 dB |
| 1960s 팝 (The Beatles) | −11.64 dB | 13.97 dB |
| 1970s 록 (Pink Floyd) | −14.47 dB | 14.82 dB |
| 재즈 (Bill Evans Trio) | −17.14 dB | 16.12 dB |
| 클래식 피아노 (Debussy) | −20.10 dB | 17.52 dB |
| 클래식 관현악 (Mahler) | −24.50 dB | 14.79 dB |

**판정**: 프리뷰는 **정규화되지 않으며** 마스터링 압축을 실제로 반영한다 → 지표 활성, RULES §3 표와 D-019에 반영. 상태 문자열이 `validated-2026-07-28`로 바뀌었고 selftest가 회귀 가드로 이를 검사한다.

**이 검증의 한계**: US 스토어프론트 · n=10 · 단일 시점. Apple이 정책을 바꾸면 무효가 되므로 **재검증 가능하도록 스크립트 설계를 위 문단에 남긴다.**

## 4. 태거 전처리 회귀 검증 (RULES §3.3) — **이 수치가 떨어지면 전처리가 깨진 것이다**

장르·악기 모델은 Essentia와 **동일한 mel**을 먹어야 한다. 어긋나면 예외가 아니라 **그럴듯한 오답**이 나오므로 일반 테스트로는 안 잡힌다. 그래서 **정답을 아는 신호**를 회귀 가드로 쓴다.

**가드**: Apple KR 차트 코호트에서 `Pop---K-pop`이 400개 스타일 중 **상위 5위 안에 드는 곡의 비율**.

| 전처리 | K-pop 중앙순위 | 평균 확률 | 상위5 진입 |
|---|---|---|---|
| mel `type=magnitude` (틀림) | 150위 | 0.0008 | 0/12 |
| **mel `type=power` (정답)** | **1위** | **0.4943** | **11/16** |

- **기준선 11/16**(2026-07-29, 코호트 앞 16곡). 이보다 크게 떨어지면 전처리 회귀를 의심한다.
- 판정 기준은 결과를 보기 전에 정했다: *"K-pop 차트 곡인데 K-pop 라벨이 상위에 없으면 전처리가 틀린 것"*.
- 격자 탐색으로 확인한 민감 파라미터: `power`(결정적) · 필터뱅크 `norm=slaney`(결정적) · `center`(경미) · 스펙트럼 스케일(경미).

**한계**: 이건 *전처리 동일성* 가드이지 *분류 정확도* 측정이 아니다. 정확도는 사람 라벨 50~100곡으로 별도 측정해야 하며(RULES §3.1.7), 그전까지 리포트는 `정확도 미측정`을 병기한다.

### 4.1 상위 k 절단 회귀 (RULES §3.1.6.1)

**임계로 곡 수를 세는 축은 라벨을 잘라 저장하면 하한이 된다.** 이건 예외가 아니라 그럴듯한 숫자로 나와서 일반 테스트에 안 걸린다 — **저장된 라벨 수를 직접 센다.**

| 검증 | 방법 | 기대 |
|---|---|---|
| 악기 라벨 완전성 | 스냅샷의 `features.instruments` 길이 | 전 레코드 **40**(= `TOP_K_INSTRUMENT`). 미만이면 `retag` 대상 |
| `retag` 멱등 | 연속 2회 실행 | 2회차 "복구 대상 없음" · **네트워크 요청 0** |
| 캐시 무효화 | `tagger_top_k_instrument`가 `engine_key`에 포함 | k를 바꾸면 캐시 미적중 → 콜드 실행. 빠지면 **다음 수집이 절단본을 되살린다** |
| 하한 표시 | `floor > 임계`인 절단 트랙 | insight·화면에 "곡 수가 하한인 곡 N"이 뜬다(복구 후에는 0이라 문구가 사라진다) |

**실행 로그(2026-07-29)**: 절단 108레코드 / 고유 101녹음 → **전건 복구, 실패 0**. 복구 후 라벨 수 min=max=40, 하한 경고 소멸. 임계별 악기 종수가 0.3→10종 · 0.2→12종 · 0.1→16종으로, **절단 때는 보이지 않던 저확률 악기가 드러났다**(예: `drums` 임계 0.1에서 57 → 100곡).

## 5. 리듬 패턴 검증 (RULES §3.1.5)

selftest가 **모델 없이**(네트워크 0) 순수 함수를 검증한다.

| 검증 | 방법 | 기대 |
|---|---|---|
| 템포 적합이 양자화를 씻는가 | 0.02초 격자에 붙인 128·143BPM 비트 시각 | 적합 오차 < 0.2%, `median(diff)`보다 정확 (실측: 128.00 vs 130.43) |
| 마디 프로파일 정규화 | 합성 정박 킥 | 합 = 1 |
| 패턴 정합 | 합성 정박 킥 | `four-on-floor`가 최고 정합 |
| 결정성 | 같은 프로파일 2회 | 동일 |
| 미해석 규약 | 비트 < 4 · 다운비트 < 3 | `RhythmUnavailable`(0으로 채우지 않음) |
| **템플릿 이름 ↔ 위치 정합** | `tresillo(8분 3+3+2)` 분수 위치 | `(0, ⅜, ¾)` — **격자와 무관한 분수로 저장**되고, 16칸 → 0·6·12 / 32칸 → 0·12·24로 렌더된다(D-038). 어긋나면 실패 |
| **앨리어싱 거부** | 트리플렛 위치(⅓)를 32칸에 렌더 | **None**(표현 불가) — 반올림해 흘리지 않는다. 24칸에서는 렌더된다 |
| **32 → 16 접기 무손실** | 32칸 프로파일을 16칸으로 접기 | 합 보존 · 접은 뒤에도 `four-on-floor` 최고 정합 · 32→24처럼 안 나뉘는 조합은 미해석 |
| **16분 tresillo = dembow 중복** | 반마디 `(0, 3⁄16, ⅜)`을 마디 끝까지 타일링 | `dembow`와 **동일 집합**임을 확인 + **그 템플릿이 원장에 없음**을 확인(2026-07-30 제거) |
| **비직교성 상한** | 전 템플릿 쌍 코사인 | 최대 쌍 상관 **0.85 초과 시 실패**. 초과는 "두 이름이 같은 것을 재고 있다"는 뜻 (반마디 tresillo 제거 후 최악 **0.683** = four-on-floor ↔ backbeat, 정박 공유라 음악적으로 당연) |
| **θ 미만 → 해당 없음** | 어느 템플릿도 쓰지 않는 칸(격자에서 파생)에만 킥 | 전 템플릿과 음의 상관 → `assigned=None`. **argmax가 이름을 뱉지 않는가** |
| **평탄 프로파일 폴백 가드** | 완전 균일한 프로파일 | 전 정합도 0 → `assigned=None`. θ를 0으로 내리면 배정이 되살아나는 것까지 확인(임계가 유일한 방어선) |
| **동점 검출** | `tie_gap`을 열어 둔 정박 프로파일 | `tie=True`로 표시되고 배정은 유지된다 — **집계에서 지워지지 않는다** |

> **픽스처 해상도 함정(실측 2026-07-30 · D-038)**: 마디당 프레임 수를 상수로 박아 둔 픽스처는 격자를 늘리면 **조용히 깨진다.** 64프레임/마디는 16칸에서 칸당 4프레임이지만 32칸에서는 **2프레임**이 되고, 부동소수 경계 오차가 임펄스를 옆 칸으로 밀어 자기유사도가 1.0 → **0.43**으로 떨어졌다. 코드가 아니라 픽스처의 결함인데 코드 결함으로 보인다(HANDOFF 방법론 메모의 그 패턴). **픽스처도 실측 예산(칸당 ~10프레임, RULES §3.1.5.2)을 지킨다** — 마디당 프레임을 `BINS`에서 파생시킨다.

> **픽스처 함정(실측)**: 임펄스 프레임을 `int()`로 잘라 넣으면 0.5초가 0.4993초가 되어 칸 경계에서 **앞 칸으로 밀린다**(4번 → 3번). 그 상태에서는 정박 킥이 `dembow`로 잡힌다. 격자 정렬 픽스처는 반드시 **반올림**한다.

> **폴백 함정(실측 2026-07-29)**: `match_templates`는 프로파일이 완전 평탄하면 노름 0으로 전 정합도를 0으로 돌려주는데, 여기에 `max()`를 씌우면 **사전 삽입 순서상 첫 키인 `four-on-floor`가 조용히 당첨된다**. "리듬 없음"이 "정박"으로 둔갑하는 경로다. `classify_rhythm`은 (a) 동점을 **이름순**으로 깨 삽입 순서 의존을 없애고 (b) θ로 배정 자체를 막는다. θ를 0으로 내리면 되살아나므로 두 경로 모두 테스트로 고정한다.

> **음의 상관 픽스처 함정(실측)**: "정박의 반대 위상"(2·6·10·14)은 이 테스트에 **부적합하다** — `four-on-floor`와는 음의 상관이지만 `trap-synco`와 +0.33이라 argmax가 다른 이름으로 도피한다. 임계가 막아야 하는 것이 바로 그 도피이므로, 픽스처는 **어느 템플릿도 쓰지 않는 칸**(1·5·9·13)을 써서 전 템플릿과 음의 상관을 만든다.

**실측 분포 (2026-07-29 · Apple KR 코호트 108곡)** — θ와 동점폭 기본값의 근거이자 한계:

| 항목 | 값 |
|---|---|
| 최고 정합도 분포 | min **−0.027** · p10 0.480 · 중앙 0.685 · p90 0.872 · max 0.969 |
| θ=0.30 미만 (해당 없음) | **4곡** (그중 1곡은 **음의 상관** — θ 없이는 `backbeat`로 집계됐다) |
| 1위−2위 차 중앙값 | 0.110 |
| 동점(차 < 0.05) | **29곡 / 108 = 27%** |
| 최소 격차 | 0.0038 (에스파 - Supernatural) |

- **이 수치들이 "판정 아닌 순위"의 실증이다.** 코호트의 1/4이 사실상 동점인데 막대그래프는 그 사실을 지운다 → RULES §4 리듬 뷰 규약이 동점 곡 수 병기를 강제하는 근거.
- **θ=0.30·동점폭 0.05는 관습값이다.** 위 분포를 보고 정한 것이므로 **케이스 오버핏 위험이 있다**(AGENTS §2.1: 기준은 도메인 근거에서 정한 뒤 결과를 본다). A&R가 재조정할 때까지 잠정값으로 표기한다.

**아직 검증하지 못한 것**: 실음악에서의 **다운비트 정확도**. 합성 클릭에는 화성·베이스 단서가 없어 픽스처가 다운비트를 과소평가한다(합성 F 0.34~0.68). 정답 채보가 붙은 코퍼스(AI Hub 등)가 생기기 전까지 `beats_per_bar`는 **집계에만** 쓴다.

## 6. 신규 지표 검증 (D-031)

전부 **정답을 아는 합성 신호**로 고정한다(§1 전략). 네트워크 0.

### 6.1 리듬 파생 3종 — 저장된 프로파일에서 재계산되므로 오디오가 필요 없다

| 검증 | 픽스처 | 기대 |
|---|---|---|

**방법**: 정서가·리듬성이 극단적으로 갈릴 것이 자명한 대조 표본을 쓰고, **판정 기준을 결과 보기 전에 고정**한다.

|---|---|
| 말러 교향곡 6번 "비극적" · 사티 짐노페디 | 낮은 각성도 · 낮은 danceability |

| `halftime_snare_ratio` | 저지클럽 원형 5곡 | 코호트 상위 20% 안 **3곡 이상** | 원장에 "판별력 없음"으로 적고 검출 규칙 승격 보류 |
| `bass_glide_ratio` | 드릴 원형 3곡 | 코호트 상위 20% 안 **2곡 이상** | 동일 — A2.1의 "드릴 축 공백"이 **스템으로도 안 풀린 것**이므로 그대로 기록한다 |
| `vocal_tuning_hardness` | 하이퍼팝 계보 5곡 | 코호트 상위 20% 안 **3곡 이상** | 동일 |
| `vocal_pitch_shift_proxy` | 하이퍼팝 계보 5곡 | 위와 동일 | 🔺 프록시라 **철회 가능성이 가장 높은 축** — 실패하면 `meter_duple_bias` 선례대로 **해석을 버리고 원시값만 남긴다** |

### 7.2.3 분리 품질 회귀 (스템이 실제로 마스킹을 풀었는가)

2026-07-29 실측(분리 전 중역 대비 1.17~1.41 → 분리 후 1.56~2.38)이 기준선이다. **같은 3곡으로 재현**해 분리 후 대비가 3곡 중 2곡 이상에서 **분리 전 값보다 오르는지** 확인한다. 못 오르면 스템 도입의 전제가 무너진 것이므로 **비용(+20~25분/일)을 지불할 근거가 없다** — 이 회귀는 모델·버전을 바꿀 때마다 돌린다(§6.4 붕괴 가드와 같은 성격).

⚠ **판정 기준을 "저역 기준선 1.71을 넘는지"로 쓰지 않는다**(2026-07-30 정정, RULES §3.8.4.3). 이 회귀가 재는 것은 **같은 곡의 전·후 변화**이므로 다른 대역의 절대값을 컷으로 쓸 이유가 없다. 코호트 규모 확인은 별개로 끝났다(n=123에서 중역 중앙 1.62 ≈ 저역 1.64, RULES §3.8.4.2) — **분포끼리 비교**가 그 주장의 올바른 형식이다.

### 7.2.4 유효성 바닥 재도출 · 재게이트 (오디오 0)

`snare_bar_profile`이 게이트에 걸린 곡에도 저장되므로 **임계를 바꿔 재판정하는 데 오디오가 필요 없다**(D-031 `syncopation_ratio` 소급과 같은 경로).

| 검사 | 방법 | 기대 |
|---|---|---|
| 재게이트 항등 | `regate_snare_axes(f, min_contrast=…)`를 같은 임계로 2회 | 2회차 = 1회차 (멱등) |
| 바닥 완화 | 임계를 대비 미만으로 내림 | 결측이던 `halftime_snare_ratio`가 저장 프로파일에서 되살아남 · `snare_axes_gated` 사라짐 |
| 바닥 강화 | 임계를 대비 초과로 올림 | 하위 축이 **결측**(0이 아님, §0) |
| 프로파일 결측 | `snare_bar_profile` 없는 레코드 | 되살리지 않는다(추측 금지) |
| 도출 재현 | `python scripts/stem_gate.py --snapshot …` | 판정 JSON에 `floor_derivation`(백분위 표 + 현 바닥의 백분위)이 함께 실린다 |

앞 4항은 `selftest_stems()`에 편입(네트워크 0·모델 0).

### 7.2.5 반쪽 마디 재현성 — 유효성 판정자 후보 (RULES §3.8.4.4 · 사전 등록)

| 검사 | 방법 | 기대 |
|---|---|---|
| 완전 반복 | 모든 마디가 같은 합성 포락 | 상관 ≈ 1 |
| 무구조 | 마디마다 다른 난수 포락 | 상관 ≈ 0 (부호 무관하게 낮음) |
| **대비는 속고 재현성은 안 속는다** | 한 마디에만 큰 피크, 나머지는 평탄 | `contrast` 높음 **and** `split_half` 낮음 — 이 조합이 이 축의 존재 이유다 |
| 마디 부족 | 다운비트 3개(=마디 2개) | 미해석(결측) — 반쪽이 각 1마디면 재현성은 정의되지 않는다 |

**채택 기준(2조건 동시)**: ① `snare_bar_contrast` p5 미만 곡에서 `snare_split_half`도 낮다 ② **정답지 5곡 중 바닥에 걸리는 곡 0** — 대비 바닥이 하던 실패(정답지 3곡 탈락)를 되풀이하면 채택하지 않는다. 실패 시 백분위 바닥 유지 + 원장에 "원리적 형식 미발견"으로 적는다.

### 7.2.6 `vocal_note_f0_spread` 해상도 독립성 (RULES §3.8.4 · 사전 등록 · **철회 조건 명시**)

철회된 `vocal_tuning_hardness`가 죽은 이유는 값이 `pyin` 격자에 지배됐고 해상도를 올려도 **수렴하지 않았다**는 것이다(0.6158 → 0.6842 → 0.6558, 비단조). 새 축은 그 실패를 원리적으로 회피한다고 주장하므로 **같은 실험으로 증명해야 한다**.

| 검사 | 방법 | 기대 | 실패 시 |
|---|---|---|---|
| 해상도 독립 | 같은 곡 보컬 스템, `resolution` 0.1 ↔ 0.05 | 값 변화 **< 10%**, 방향 일관 | **즉시 철회**(같은 실패다) |
| 양자화 감시 | 코호트 고유값 수 | 표본의 절반 이상 | 고유값이 적으면 격자를 재고 있다 |
| 비브라토 분리 | `vocal_vibrato_strength`와의 코호트 상관 | \|r\| < 0.5 | 비브라토를 재고 있는 것이므로 해석 폐기 |
| 합성 하한/상한 | 완전 고정 f0 ↔ ±50센트 흔들리는 f0 | 0 ↔ 큰 값, 단조 | 정의 결함 |

### 7.3 하이햇 축 채택 게이트 (RULES §3.1.5.3 · 사전 등록)

**게이트 코호트는 §7.2.2와 같다**(당일 차트 100곡 + 정답지) — 비교 모집단이 하나여야 백분위가 의미를 갖는다.

| 가설 | 축 | 정답지 | 통과 기준 | 실패 시 |
|---|---|---|---|---|
| H1 | `hihat_roll_ratio` | 저지클럽 원형 (확대안 20곡, [DRAFT](../../docs/DRAFT-jersey-club-answer-sheet.md) · A&R 확정 대기) | **측정된 정답지의 60% 이상**이 상위 20% · 판정 성립 최소 표본 **10곡** | "롤이 저지클럽의 서명"이라는 통설을 **이 축으로는 확인 못 했다**고 적는다 |
| H2 | `hihat_triplet_bias` | 드릴 원형 3곡 | 상위 20% 안 **2곡**(=67%) | **트랩과의 사운드 경계 미분리**로 적는다(케이스북 CASE 10 가설의 실측 지지) — "측정 결함"이 아니다 |

> **기준을 비율로 쓰는 이유**(2026-07-30): 정답지 크기가 바뀌어도 같은 엄격도를 유지해야 한다. 기존 `5곡 중 3곡`은 **60%**였고 확대 후에도 60%다 — 확대의 목적은 컷을 낮추는 것이 아니라 **검정력을 올리는 것**이다(D-037에서 5곡·컷 하나로는 약한 신호와 없는 신호가 구별되지 않음이 드러났다). 최소 표본 10곡 미만이면 `unmeasured`이며 판별력 판정이 아니다.

**순수 함수 검사**(네트워크 0 · `selftest_rhythm`에 편입):

| 검사 | 방법 | 기대 |
|---|---|---|
| 롤 하한 | 16분 위치에만 에너지 | `hihat_roll_ratio` = 0 |
| 롤 상한 | 32분 홀수 칸에만 | 1.0 |
| 트리플렛 하한 | 8분 이진 위치에만(24칸의 `i%3==0`) | `hihat_triplet_bias` = 0 |
| 트리플렛 상한 | 트리플렛 전용 칸에만 | 1.0 |
| **격자 앨리어싱 거부** | 32칸에 트리플렛 템플릿 렌더 시도 | **제외 + 이유 반환**(반올림해 흘리지 않는다) |
| 32 → 16 접기 무손실 | 32칸 프로파일을 접어 16칸 지표 계산 | 직접 16칸 계산과 일치(부동소수 허용오차) |
